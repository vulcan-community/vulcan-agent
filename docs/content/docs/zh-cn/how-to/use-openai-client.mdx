---
title: 用 OpenAI SDK 调 Vulcan
description: 用 `openai` Python SDK 或 `curl` 直接驱动 Vulcan。
---

Vulcan 对外暴露的就是 OpenAI Chat Completions——任何说这个 API 的东西都能驱动它,不需要 Vulcan 专属客户端。

## 1. 起 gateway

```python
from pathlib import Path
from vulcan.gateway.gateway import Gateway

Gateway(home_dir=Path("~/.vulcan").expanduser()).start()
```

监听在 `http://0.0.0.0:4000`。

## 2. 把 OpenAI SDK 指过来

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:4000/v1",
    api_key="anything",  # 不会用,但 SDK 要求有
)

reply = client.chat.completions.create(
    model="claude-code",
    messages=[{"role": "user", "content": "你好"}],
    extra_headers={"X-Session-Id": "my-session"},
)
print(reply.choices[0].message.content)
```

几件事要知道:

- **`model` 是 runtime 名字,不是 LLM。** 填一个你启用了的 runtime——在任意 channel 发 `/runtime` 就能看到列表(`claude-code`、`codex`、`base-openai`……)。你传进去的这个字符串决定这一轮由哪个 agent runtime 处理。
- **`X-Session-Id` 是把多轮串起来的关键。** 每次都传同一个,Vulcan 会把之前的对话作为 history 回放给 runtime。不传就走 `default` session。HTTP 这条路在 gateway 里 `channel_id` 固定是 `"gateway"`。
- **`model` 就是隐式的 `/switch`。** Middleware 会在派发**之前**把 `body["model"]` 写进 session 的 `.meta.json` sidecar,后续同一个 `X-Session-Id` 上的 turn 只要不换 `model`,就一直跑在这个 runtime 上。`"model"` 省掉不传时保持现有绑定;从未绑定过、又不传 `"model"` 的全新 session 回落到 `vulcan.json` 里的 `config.default_runtime`。

## 3. 等价的 `curl`

```bash
curl http://localhost:4000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "X-Session-Id: my-session" \
  -d '{
    "model": "claude-code",
    "messages": [{"role": "user", "content": "你好"}]
  }'
```

## 从 API 切换 runtime

两种办法,都是按 session 的:

1. **传一个不一样的 `model`。** Middleware 派发前先把它落到当前 session 的 meta 里,下一次同 `X-Session-Id` 的请求哪怕不传 `model`,也会继续走新 runtime。
2. **把 `/switch <name>` 当消息发。** 效果一样,只是从聊天侧触发。不同飞书 chat、不同 `X-Session-Id` 各自保留自己的绑定 —— `/switch` 只影响发命令的那个 session。

```python
client.chat.completions.create(
    model="claude-code",   # 处理这轮 /switch 同时重绑这个 session
    messages=[{"role": "user", "content": "/switch codex"}],
    extra_headers={"X-Session-Id": "my-session"},
)
```

这一次之后,`my-session` 就绑在 `codex` 上。没有全局"当前 runtime"这回事 —— 别的 `X-Session-Id`、别的 channel 完全不受影响。
