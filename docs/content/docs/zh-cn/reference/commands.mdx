---
title: 斜杠命令
description: 所有已注册斜杠命令的参数与输出格式。
---

斜杠命令是控制面消息，在 gateway 分派到 agent 运行时之前由 `CommandManager` 拦截匹配。命令消息 **不会** 写入 session 记录；其响应以 `vulcan-system` 的 `ChatCompletion` 形式返回。

## 匹配规则

同时满足两条时，消息被识别为命令：

1. 原始文本以 `/` 开头。
2. 首个空白分隔 token（去掉前导 `/`）等于已注册的命令名。

剩余 token 作为参数。

## 已注册命令

| 名称             | 参数                                          | 说明                                                                                 |
| ---------------- | --------------------------------------------- | ------------------------------------------------------------------------------------ |
| `/new`           | —                                             | 在当前 conversation 上轮换出一段全新 session；沿用上一段 session 的运行时绑定。     |
| `/resume`        | `<session_id>`                                | 把当前 conversation 指向一段已有的 session（必须属于同一个 conversation）。         |
| `/switch`        | `<runtime_name>`                              | 切换**当前 session** 的运行时绑定。                                                  |
| `/sessions`      | —                                             | 列出当前 conversation 下的所有 session，最新在前。                                   |
| `/conversations` | —                                             | 列出所有 channel 下的全部 conversation。                                             |
| `/session`       | `<channel>/<session_id>` 或 `<session_id>`    | 显示指定 session 的原始 JSONL。                                                      |
| `/runtime`       | —                                             | 列出所有已知运行时及其状态（`enabled` / `disabled` / `uninstalled`）。               |
| `/version`       | —                                             | 显示已安装的 `vulcan-agent` 版本。                                                   |
| `/status`        | —                                             | 显示当前 conversation 指向的 session，以及它的运行时和模型配置。                     |
| `/help`          | —                                             | 列出所有可用斜杠命令。                                                               |

顺序即 `Gateway._register_commands` 的注册顺序：`new`、`resume`、`switch`、`sessions`、`conversations`、`session`、`runtime`、`version`、`status`、`help`。

## 两层身份

**conversation** 是稳定的用户侧地址（飞书 `chat_id`、HTTP 的 `X-Conversation-Id` header），跨 `/new` 保持不变。**session** 是一份具体的 transcript —— 一对 `<session_id>.jsonl` + `<session_id>.meta.json`，id 是 12 个十六进制字符随机生成。每个 conversation 在 `<channel_id>/_conversations/<conversation_id>.json` 下有一个指针文件，指向它当前的 session。`/new` 轮换这个指针；`/resume` 把指针移到一段已有 session。存储布局见 [Sessions & conversations](./sessions)。

## `/new`

在当前 conversation 上分配一段全新的 session，把 conversation 指针改过去，**沿用**上一段 session 的运行时绑定（没有上一段 session 时回落到 `config.default_runtime`）。

**参数** —— 无。

**行为**

调用 `session_manager.rotate_current_session(channel_id, conversation_id, default_runtime)`：写一对新的 `<session_id>.jsonl` + `.meta.json`，并覆写 `_conversations/<conversation_id>.json`。旧 session 的 transcript 留在盘上不动 —— 要回去用 `/resume <old_session_id>` 即可。

**输出**

成功：

```
Started new session <session_id> (runtime: <runtime_name>).
```

未预期的异常：

```
Failed to start new session: <ExceptionType>: <message>
```

## `/resume`

把当前 conversation 指向一段已有的 session。拒绝跨 conversation 恢复 —— 目标 session 的 meta 里 `conversation_id` 回指必须和调用方的 conversation 一致。

**参数**

| 位置 | 名称         | 必填 | 说明                                                    |
| ---- | ------------ | ---- | ------------------------------------------------------- |
| 0    | `session_id` | 是   | 当前 channel 下已存在的一段 session id，12 位十六进制。 |

**行为**

1. 确认该 session 在当前 channel 下存在。
2. 读 session 的 meta，核对其 `conversation_id` 和调用方的 conversation 一致。
3. 调 `session_manager.set_current_session_id(channel_id, conversation_id, sid)` —— 只覆写 conversation 指针文件，session 自己的 meta 不动。

**输出**

成功：

```
Resumed session <session_id> (runtime: <runtime_name>).
```

缺少位置参数：

```
Usage: /resume <session_id>. Run /sessions to see available ids.
```

当前 channel 下找不到：

```
Session '<session_id>' not found in channel '<channel_id>'.
```

session 没有 meta（无法确认归属）：

```
Session '<session_id>' has no meta — cannot confirm it belongs to this conversation.
```

session 属于别的 conversation：

```
Session '<session_id>' belongs to a different conversation ('<actual>'), not '<conversation_id>'.
```

未预期的异常：

```
Failed to resume: <ExceptionType>: <message>
```

## `/switch`

把**当前 session** 重绑到另一个运行时。其它 session 各自保留自己的绑定 —— 运行时选择是按 session 的。conversation 指针不动，只重写目标 session 的 `.meta.json`。

**参数**

| 位置 | 名称           | 必填 | 说明                                           |
| ---- | -------------- | ---- | ---------------------------------------------- |
| 0    | `runtime_name` | 是   | 已注册且处于 **enabled** 状态的运行时名称。    |

**行为**

通过 `RuntimeManager.get_runtime(name)` 查找；返回 `None` 时回复提示未启用，绑定不变。否则通过 conversation 指针解析出当前 session id，调 `session_manager.set_session_runtime(channel_id, session_id, name)`，重写该 session 的 `.meta.json` sidecar。整个函数体被一个宽泛的 `try/except` 包住，避免未来可能引入的状态错误直接把请求打挂。

**输出**

```
Switched this session to runtime: <runtime_name>.
```

缺少位置参数时：

```
Usage: /switch <runtime_name>. Run /runtime to see enabled runtimes.
```

名称未启用时：

```
Runtime '<runtime_name>' is not enabled. See /runtime.
```

发生未预期的异常时：

```
Failed to switch: <ExceptionType>: <message>
```

## `/sessions`

列出属于**当前 conversation** 的 session（别的 conversation 不显示），按 `.jsonl` ctime 降序。

**参数** —— 无。

**输出**

```
Sessions for <channel>/<conversation> (current=<session_id>):
  [*] <session_id>  <ISO-8601 ctime>  runtime=<name>
  [ ] <session_id>  <ISO-8601 ctime>  runtime=<name>
  ...
```

`[*]` 标记 conversation 当前指向的 session。没有绑定时 `runtime=—`。空列表：

```
Sessions for <channel>/<conversation> (current=<session_id>):
  (none)
```

## `/conversations`

列出所有 `_conversations/` 目录里的 conversation。`[*]` 标记调用方自己的 conversation。

**参数** —— 无。

**输出**

```
Conversations:
  [*] <channel>/<conversation>  current=<session_id> runtime=<name> sessions=<count>
  [ ] <channel>/<conversation>  current=<session_id> runtime=<name> sessions=<count>
  ...
```

- `current=` 是 conversation 指针指向的 session。
- `runtime=` 是那个 session 的运行时绑定（未绑定时为 `—`）。
- `sessions=` 是 meta 的 `conversation_id` 回指匹配的 session 数。

空列表：

```
Conversations:
  (none)
```

## `/session`

打印指定 session 的原始 JSONL 记录。

**参数**

| 位置 | 名称 | 必填 | 说明                                                                                                    |
| ---- | ---- | ---- | ------------------------------------------------------------------------------------------------------- |
| 0    | spec | 是   | `<channel>/<session_id>` 或仅 `<session_id>`。后者必须唯一匹配一个 session 文件。                       |

**行为**

- 包含 `/`：解析为 `<home>/sessions/<channel>/<session_id>.jsonl`。
- 不含 `/`：按 `<home>/sessions/*/<session_id>.jsonl` glob。零匹配或多匹配都以错误回复，不再 assert。

**输出**

文件内容，末尾附加一个换行符。

错误回复：

```
Usage: /session <channel>/<session_id> or /session <session_id>. Run /sessions to see available ids.
```

```
Session '<spec>' not found.
```

```
Session id '<spec>' matches multiple channels: [<ch>, <ch>, ...]. Use /session <channel>/<session_id>.
```

```
Failed to read session: <ExceptionType>: <message>
```

## `/runtime`

列出 `KNOWN_RUNTIMES` 中的每个名称及当前状态。

**参数** —— 无。

**输出**

```
Runtimes:
  [*] <name>          — <status>
  [ ] <name>          — <status>
  ...
```

- `[*]` 标记**当前 session** 的运行时 —— 顺着 conversation 指针找到当前 session，再读它的 sidecar meta 解析；未写入时回落到 `config.default_runtime`。只有状态为 `enabled` 的行会被标记。
- `<status>` 取值：`enabled`、`disabled`、`uninstalled`，定义见 [运行时](./runtimes)。
- 名称列左对齐，宽度 16 字符。

## `/version`

**参数** —— 无。

**输出**

```
vulcan-agent <VERSION>
```

`<VERSION>` 取自 `vulcan.version.VERSION`。

## `/status`

报告调用方的 conversation、它当前指向的 session、该 session 的运行时绑定，以及该运行时使用的模型配置。

**参数** —— 无。

**行为**

- 通过 conversation 指针解析当前 session（第一次接触时会自动装一个指针并分配一段绑在 `config.default_runtime` 上的新 session）。
- 通过 `session_manager.get_session_runtime()` 读 session 的运行时绑定。为空时回落到 `config.default_runtime`，绑定字段会标注未绑定。
- 直接按非空行统计 `.jsonl` 里的条目数 —— 文件不存在就是 `0`。
- 通过 `RuntimeManager.get_runtime(name)` 查找解析出来的运行时。返回 `None` 时，`class` 显示 `—`，`status` 回落到 `runtime_manager.status`（或 `not-registered`）。
- 模型配置取自 `runtime.agent_config.model`。`api_key` 从不外露 —— 只显示 `set` 或 `(empty — using SDK default)`。

**输出**

```
Conversation:
  channel         : <channel_id>
  conversation    : <conversation_id>
  current session : <session_id>
  items           : <int count of JSONL lines>
  runtime         : <runtime_name bound to this session, or '(unbound → default: <default_runtime>)'>

Runtime:
  name       : <resolved runtime name>
  status     : <enabled | disabled | uninstalled | not-registered>
  class      : <BaseRuntime subclass short name, e.g. ClaudeCodeRuntime>

Model:
  name       : <ModelConfig.name>
  provider   : <ModelConfig.provider>
  base_url   : <ModelConfig.base_url or '(default)'>
  api_key    : <'set' if non-empty else '(empty — using SDK default)'>
```

## `/help`

遍历 `CommandManager.list_commands()`（注册顺序），打印每个命令的名称与类级 `description`。

**参数** —— 无。

**输出**

```
Commands:
  /<name> — <description>
  ...
```

## 响应格式

每个命令返回由 `system_completion(text)` 构造的 `ChatCompletion`：

```json
{
  "id": "<uuid>",
  "object": "chat.completion",
  "model": "vulcan-system",
  "choices": [
    {
      "index": 0,
      "finish_reason": "stop",
      "message": { "role": "assistant", "content": "<text>" }
    }
  ]
}
```
